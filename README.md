# مخزن baz

این مخزن حاوی یک پروژه سبک وب است که ترکیبی از فایل‌های HTML و کمی کدهای پایتون دارد. بر اساس تحلیل زبان‌ها، ترکیب زبان‌ها به‌صورت زیر است:
- HTML: 88.9%
- Python: 11.1%

این سند راهنمای کلی برای مرور، اجرا و مشارکت در پروژه را به زبان فارسی فراهم می‌کند.

## معرفی
پروژه baz یک وب‌سایت / مجموعه صفحات استاتیک است که برای نمایش محتوای وب طراحی شده است و در کنار آن چند اسکریپت پایتون برای تسهیل توسعه یا پردازش داده وجود دارد. هدف این مستند کمک به توسعه‌دهندگان و همکاران جهت راه‌اندازی محلی، توسعه و ارسال تغییرات است.

## ساختار کلی پوشه‌ها (نمونه)
در این مخزن ساختار معمولاً به این شکل است (ممکن است در پروژه واقعی تفاوت داشته باشد):
- /index.html — صفحهٔ اصلی
- /assets/ — CSS، تصاویر، جاوااسکریپت
- /docs/ — مستندات یا صفحات اضافی
- /scripts/ یا /tools/ — اسکریپت‌های پایتون
- requirements.txt — (در صورت وجود) وابستگی‌های پایتون

برای دیدن ساختار دقیق از `ls` یا ابزار مرورگر فایل استفاده کنید.

## اجرا به‌صورت محلی

اگر فقط صفحات استاتیک دارید:
- ساده‌ترین روش، اجرای یک سرور HTTP محلی:
  - با Python 3:
    ```bash
    python3 -m http.server 8000
    ```
    سپس مرورگر را باز کنید و به `http://localhost:8000` بروید (در مسیر ریشهٔ پروژه).

اگر اسکریپت‌های پایتون وجود دارند:
1. محیط مجازی بسازید و فعال کنید:
   ```bash
   python3 -m venv .venv
   source .venv/bin/activate  # Unix / macOS
   .venv\Scripts\activate     # Windows (PowerShell)
   ```
2. وابستگی‌ها را نصب کنید (در صورت وجود `requirements.txt`):
   ```bash
   pip install -r requirements.txt
   ```
3. اسکریپت مورد نظر را اجرا کنید:
   ```bash
   python scripts/example.py
   ```

توضیح: نام پوشه‌ها و فایل‌های پایتون ممکن است متفاوت باشد؛ لطفاً ساختار واقعی را قبل از اجرا بررسی کنید.

## راهنمای توسعه و سبک
- HTML: از ساختار معنایی (semantic HTML) و رعایت قابلیت دسترسی (accessibility) استفاده کنید.
- CSS/JS: فایل‌ها را در پوشهٔ `assets/` یا `static/` نگه دارید.
- Python:
  - از نسخهٔ Python 3.8+ استفاده کنید.
  - قواعد PEP8 را رعایت کنید.
  - برای بسته‌های جدید، آن‌ها را به `requirements.txt` اضافه کنید.
  - تست‌های کوچک برای منطق پایتون بنویسید در صورت نیاز.

## نحوهٔ مشارکت
1. یک شاخهٔ جدید از شاخهٔ اصلی بسازید:
   ```bash
   git checkout -b feature/my-change
   ```
2. تغییرات خود را اعمال، استیج و کامیت کنید:
   ```bash
   git add .
   git commit -m "توضیح تغییر"
   ```
3. شاخه را پوش کنید و درخواست Pull Request بسازید:
   ```bash
   git push origin feature/my-change
   ```
4. در توضیح PR خود بنویسید که چه مشکلی حل شده و چگونه تست شده است.

## گزارش باگ و درخواست ویژگی
برای گزارش اشکال یا پیشنهاد ویژگی جدید، یک Issue جدید در بخش Issues مخزن باز کنید و:
- قدم‌هایی که مشکل را بازتولید می‌کنند بنویسید
- خروجی‌ها و پیام‌های خطا را قرار دهید
- نسخهٔ مرورگر / سیستم یا نسخهٔ پایتون را قید کنید (در صورت مرتبط بودن)

## امنیت و داده‌ها
- اطلاعات حساس (مثل کلیدهای API) را هرگز در مخزن قرار ندهید.
- اگر کلیدی به اشتباه در مخزن قرار گرفت، آن را فوری باطل کنید و تاریخچهٔ git را پاک کنید.

## تست و اعتبارسنجی
- برای HTML از ابزارهای اعتبارسنجی (مثل W3C validator) استفاده کنید.
- اگر تست‌های پایتون اضافه شد، از pytest یا unittest برای اجرای آن‌ها بهره ببرید:
  ```bash
  pytest
  ```
